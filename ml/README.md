# ML: predicting `hours` for timesheet work entries

Self-contained offline pipeline (no app code is touched) that generates synthetic
`users` / `clients` / `work_entries` matching the app schema, trains models to predict
`hours`, and writes an evaluation report.

| file | purpose |
|---|---|
| `generate_data.py` | seeded synthetic data generator + time-based train/test split |
| `train.py` | features, baselines, LightGBM + Ridge, evaluation, report |
| `REPORT.md` | generated results report (committed; regenerated by `train.py`) |
| `data/generator_config.json` | persisted generator config, seed and split date |

## Run

From the repository root (Python 3.10+):

```bash
python -m venv ml/.venv && source ml/.venv/bin/activate
pip install -r ml/requirements.txt
python ml/generate_data.py && python ml/train.py
```

Takes a few seconds. Outputs:

- `ml/data/{users,clients,work_entries,train,test}.csv` (+ `user_profiles.csv`, the
  generator's hidden per-user parameters, never used as features) — git-ignored.
- `ml/REPORT.md` — dataset stats, methodology, results tables, feature importance.
- `ml/artifacts/metrics.json`, `ml/artifacts/test_predictions.csv` — git-ignored.

Both scripts are deterministic: same seed → identical CSVs and `REPORT.md`.
`python ml/generate_data.py --seed 7` produces a different dataset; `train.py` accepts
`--data-dir`, `--artifacts-dir` and `--report`.

If `lightgbm` is not installed, `train.py` falls back to scikit-learn's
`HistGradientBoostingRegressor`.
